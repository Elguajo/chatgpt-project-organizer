# Change Request

When the user changes product scope:

1. state the requested change;
2. identify affected Brief/Architecture/phase assumptions;
3. classify whether it is compatible with current MVP or a post-MVP feature;
4. update canonical docs before coding when the change is material;
5. add an ADR for a hard-to-reverse privacy/permission/architecture decision;
6. adjust ROADMAP without erasing completed evidence;
7. implement in the appropriate phase.
